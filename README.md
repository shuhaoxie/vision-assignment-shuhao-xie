# 我的视觉组大作业

## 所选路线

路线 B：运动预测与瞄准。

实现位于 `aiming/src/lib.rs` 的 `aim` 函数。

主要实现：

- 根据历史观测预测目标的平移和自旋。
- 补偿观测延迟、发射延迟和弹丸飞行时间。
- 根据预计命中时刻的装甲板朝向选择目标板。
- 固定板子编号，通过迭代修正飞行时间和瞄准位置。
- 检查迭代收敛情况、弹道可达性和正面入射条件，决定是否开火。

## 环境与依赖

- 开发环境：Mac M1、VS Code。
- Rust / Cargo，Rust 版本至少为 1.98.1。
- macOS 需要安装 Xcode Command Line Tools。
- 仿真界面需要桌面环境和支持 Metal 的图形驱动。
- Rust 项目依赖由 Cargo 根据 `Cargo.lock` 安装。
- 不需要 OpenCV、相机或真实云台。

## 运行方法

在仓库根目录打开终端，进入瞄准项目：

```bash
cd aiming
```

静止目标场景：

```bash
cargo run --locked -- --config scenarios/stationary.json
```

自旋目标场景：

```bash
cargo run --locked -- --config scenarios/spinning.json
```

平移与自旋同时发生的场景：

```bash
cargo run --locked -- --config scenarios/moving.json
```

每次运行一个场景。在终端按 Control+C 停止当前程序后，再启动下一个场景。

## 实现思路

先根据炮口到目标中心的距离粗估飞行时间，结合观测年龄和发射延迟，预测四块装甲板在预计命中时刻的姿态，选择正面朝向炮口的装甲板。

随后保持装甲板编号不变，交替计算未来板子位置和弹道飞行时间。当相邻两次飞行时间之差小于 0.000001 秒时认为收敛，最多迭代 20 次。

缺少观测、弹道不可达或迭代未收敛时不开火。收敛后，使用弹丸相对装甲板的速度与装甲板外法线检查入射方向，仅在能够从正面进入时请求开火。

## 云台能动了，然后呢？

在[控制组的作业](https://github.com/HKUAstar/control-training-template)中，
lyf 把 yaw、pitch 云台教具交给了控制组。这次我们假设他们已经完成程序：
云台可以回正、跟随目标角度，也能在调试时停止输出。

看到云台终于不再反复点头，lyf 松了一口气：“现在能不能让它自己盯着目标转？”

控制组也想试试。他们留出了目标角度接口，准备接上视觉系统。
但视觉组还得回答两个问题：相机画面里的哪一块是装甲板？
就算知道它现在在哪里，等弹丸飞过去，它又会转到哪里？

这一次，你负责实现视觉链路中的一段。为了让你能在自己的电脑上独立完成，
我们提供录像、模型、标定和瞄准仿真器。本次不需要真实教具、相机、电机或控制板，
也不要求与控制组固件通信。故事中的联调只是背景，不是额外的硬件任务。

## 两条路线，任选其一

**只需完成检测或瞄准中的一项，不要求两项都做。两条路线互不依赖。**

| 路线 | 你负责什么 | 已提供什么 | 从哪里开始 |
| --- | --- | --- | --- |
| 检测 | 从视频检测装甲板，用 PnP 恢复三维角点，导出 JSONL | 预训练模型、比赛片段、相机标定 | [detection/README.md](detection/README.md) |
| 瞄准 | 根据延迟送达的目标状态预测装甲板位置，决定瞄准角和开火时机 | 精确的历史观测、弹道工具、3D 仿真、MCAP 回放 | [aiming/README.md](aiming/README.md) |

检测路线语言不限，推荐 Python、C++ 或 Rust，不需要训练模型。
瞄准路线使用 Rust，不需要实现检测器、跟踪器或状态估计。
两者都允许使用参考资料和 AI 工具，但你需要能够解释自己的实现并定位问题。
